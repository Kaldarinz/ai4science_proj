## Проверки

Из корня проекта с установленными зависимостями [`requirements.txt`](requirements.txt):

```sh
.venv/bin/python -m pytest tools/tests checks/verifier checks/tests tests -q
.venv/bin/python checks/verifier/run.py dry
```

Тесты проверяют реализацию и независимый договор о данных/рядах.
`dry` записывает технический манифест в `results/verifier/dry.json`;
он не запускает resampling и не выдаёт вывод об устойчивости.
Инструкция — [`checks/verifier/README.md`](checks/verifier/README.md).

Извлечение утверждений отдельно проверяет `checks/check.py` (нужны PDF).
Рабочий договор v1 записан в `checks/claims_spec.md`, §8–9 и
`checks/results_spec.md`, §5–6: частота утверждений на уровне статей,
разрешительное сопоставление с полным аудитом и исходы по каждому утверждению
без голосования большинством. Конвейер сравнения уже предоставлен;
AI4Science читает статьи, обосновывает сопоставления и интерпретирует результаты,
но не пишет код. Работа идёт **по одной статье**: слепое извлечение →
сопоставление → проверка; остальные статьи пока могут быть не прочитаны.
После извлечения и фиксации записей этой статьи:

```sh
id=80094
.venv/bin/python checks/check.py --article "$id"
.venv/bin/python checks/verifier/run.py dry --article "$id"
.venv/bin/python -m pytest checks/verifier -q
.venv/bin/python -m src.comparison prepare --article "$id"
# Агент заполняет results/articles/$id/matching_audit.csv по контексту кандидатов.
.venv/bin/python -m src.comparison build --article "$id" --stage draft
# Зафиксировать записи перед проверкой готовности.
.venv/bin/python checks/check.py --article "$id" --analysis draft
```

Следующую статью извлекать в новом контексте, без предыдущих численных
результатов. Ошибка требует возобновить конкретный шаг этой статьи, а не
перезапускать весь корпус. Изменения других статей не сбрасывают готовый
checkpoint; общие изменения правил, схемы или кода могут его инвалидировать.
Когда корпус готов к сборке:

```sh
.venv/bin/python -m src.comparison aggregate
# Зафиксировать общие записи перед проверкой готовности.
.venv/bin/python checks/check.py --analysis draft
# После проверки куратором и защищённого matching_review.json:
.venv/bin/python -m src.comparison build --stage final
# Зафиксировать финальные записи перед проверкой готовности.
.venv/bin/python checks/check.py --analysis final
```

Эти команды пока не обязаны проходить: агенту ещё предстоит закончить чтение
и подготовить научный аудит. Конвейер не придумывает решения или одобрение.
Реестр чтения привязан ко всем предоставленным PDF, включая SI; непрочитанное
не считается отсутствием утверждений. Корпус окончательный: все 41 статья
анализируются, а куратор проверяет извлечение и сравнение после их подготовки.
Автоматические проверки не гарантируют полноту и смысловую верность извлечения.
Сборка черновика проверяет checkpoint каждой полностью прочитанной статьи,
включая статьи без утверждений или численных кандидатов; решения не
переопределяются. Финальный результат требует одобрения конкретных
входов/сопоставлений куратором. Изменения договора раскрываются,
затронутые результаты пересчитываются. Подробности схем — в спецификациях.

## Последовательный запуск оставшихся статей

Куратор сначала проверяет и фиксирует изменения инфраструктуры. Затем **как
`aiagent`**, из корня проекта:

```sh
.venv/bin/python ops/run_articles.py --dry-run    # только показать очередь, без API
.venv/bin/python ops/run_articles.py --limit 1    # первый запуск: одна статья
.venv/bin/python ops/run_articles.py              # после просмотра лога — остальные
```

Каждая статья получает отдельный `ai4science run` с новым контекстом
(`goose run --no-session`) и коротким заданием только для своего ID.
По умолчанию используется `smart_approve`; смена режима — `--mode auto`.
Режим может запросить одобрение: stdin закрыт, зависший процесс ограничен
`--timeout` (по умолчанию 1800 секунд). Нет автоматических повторов.

Порядок берётся из `data/corpus.csv`; очередь сохраняется в `queue.json` рядом
с логами. Готовые статьи пропускаются **только после** независимой проверки
article draft и актуальности успешного article dry-артефакта. После каждого
агента эти проверки выполняются снова. Ненулевой код, незавершённое извлечение,
устаревший checkpoint/preflight или грязное рабочее дерево останавливают цикл.
Куратор разбирает причину; повторный запуск заново проверяет готовые статьи
и продолжает оставшиеся. Скрипт ничего не добавляет в индекс и не коммитит.

Приватные логи stdout/stderr и очередь находятся в
`$HOME/ai4science-batch/<запуск>/` (`--log-dir` позволяет выбрать другой каталог
вне проекта). `--dry-run` не запускает даже чекер и не удостоверяет готовность.
Одновременный второй цикл в том же checkout блокируется. Ctrl-C, SIGTERM
и timeout завершают группу процессов текущего запуска. Агрегация и одобрение
человеком-куратором не выполняются. Новая сессия изолирует историю диалога,
не общие файлы: ограничения `AGENTS.md` на чтение численных результатов остаются.

## Где что лежит

- [`AGENTS.md`](AGENTS.md) — задачи, ограничения и протокол агента.
- [`tools/ablation_db.py`](tools/ablation_db.py) — API только чтения снимка;
  [`tools/series.py`](tools/series.py) — чистые вычисления.
- [`checks/results_spec.md`](checks/results_spec.md) — договор API и результатов.
- `data/corpus.csv`, `data/files.csv`, `data/articles/` — все 41 статья снимка:
  41 основной PDF и 8 PDF приложений, скопированных из файлового сервиса БД.
  PDF остаются локально и исключены из Git; роли и SHA-256 записаны в `files.csv`.
  Извлечение утверждений охватывает весь корпус независимо от наличия рядов.
- `results/claims.csv`, `results/no_claims.csv` — извлечённые утверждения и
  объяснения их отсутствия; не дополнены этой миграцией.
- `results/articles/<id>/` — контекст кандидатов, научный аудит и проверяемый
  черновик сравнения отдельной статьи. Общие результаты производятся сборкой.
- [`src/comparison/`](src/comparison/) — готовый конвейер сравнения;
  `tests/` — его синтетические тесты. Инструкция —
  [`src/comparison/README.md`](src/comparison/README.md).
